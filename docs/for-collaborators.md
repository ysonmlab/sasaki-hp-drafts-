# for-collaborators.md（共同作業者むけ・かんたんガイド）

このプロジェクトで **デザイン修正（HTML/CSSの編集）** を担当する方むけの手順書です。  
GitHub や VS Code を初めて使う前提で、順番どおりに進めれば作業できるように書いています。

> あなたの役割：`drafts/` フォルダの中にある「たたき台のHTML」を編集して、デザインを修正すること。  
> 修正したものが、最終コード化のための「デザイン見本」になります。

> ✅ いちばん大事なルール：**`drafts/` フォルダの中だけを編集**してください。
> 他のフォルダ（`assets/` や `index.html` など）は触らないでください。
> こうするとファイルがぶつからず、安全に作業できます。

---

## 用語（最初にこれだけ）

| 言葉 | かんたんな意味 |
|---|---|
| リポジトリ（repo） | プロジェクトのファイル一式が入った「箱」。GitHub上にある。 |
| クローン（clone） | その箱を自分のパソコンにコピーしてくること。 |
| コミット（commit） | 変更の「セーブポイント」を作ること。 |
| 同期（sync） | GitHubから最新を受け取り、自分の変更をGitHubに送ること。 |

全部おぼえなくてOK。手順の中で出てきます。

---

## STEP 0. 準備（最初の1回だけ）

### ① GitHub の招待を承認する
1. オーナーから「招待した」と連絡が来たら、GitHub に届く**メール**を開く。
   （または https://github.com/notifications ）
2. 「**Accept invitation**（招待を承認）」ボタンを押す。
   → これでこのプロジェクトを編集できるようになります。

### ② 必要なソフトを入れる（無料）
1. **Git**：https://git-scm.com/download/win からダウンロードして、表示のまま「次へ」でインストール。
2. **VS Code**（編集ソフト）：https://code.visualstudio.com/ からダウンロードしてインストール。
3. VS Code を開き、左の四角アイコン（拡張機能）から以下を検索して **Install**：
   - **Japanese Language Pack**（日本語化・任意）
   - **Live Preview** または **Live Server**（ブラウザ確認用・どちらかでOK）

### ③ 名前の設定（最初の1回）
VS Code の上メニュー「ターミナル」→「新しいターミナル」を開き、次の2行を貼って Enter
（名前とメールは自分のものに置き換え）：

```
git config --global user.name "あなたの名前"
git config --global user.email "あなたのメール"
```

> ⚠️ これは「コミットに**誰が変更したか**の名前を刻む」設定です。
> **GitHubへのログイン（連携・認証）とは別物**で、ログインは次の STEP 1（clone）や
> 変更を送るとき（同期）に出るログイン画面で行います。③だけでは連携になりません。

---

## STEP 1. プロジェクトを自分のパソコンに取り込む（clone・最初の1回）

1. VS Code を開く。
2. `Ctrl + Shift + P` を押し、出てきた入力欄に **「clone」** と打ち、
   **「Git: Clone」** を選ぶ。
3. 次の住所（URL）を貼って Enter（オーナーから渡されたリポジトリのURLに置き換える）：
   ```
   https://github.com/{オーナーのユーザー名}/{リポジトリ名}.git
   ```
4. 保存場所を聞かれるので、分かりやすい場所（デスクトップ等）を選ぶ。
5. 初回はGitHubのログイン画面が出る → ログインして許可（これが「連携」）。
6. 「開きますか？」と出たら **「開く」**。

→ これでプロジェクト一式が手元に入りました。左側にファイル一覧が出ます。

---

## STEP 2. 編集する（`drafts/` の中だけ）

1. 作業を始める前に、まず**最新を取り込む**：
   左下の **🔄（同期）アイコン** をクリック（GitHubの最新の状態を受け取る）。
2. 左のファイル一覧で **`drafts/` フォルダ**を開き、担当のHTMLファイルを開く
   （例：`drafts/about.html`。どのファイルかはオーナーに確認）。
3. デザインを修正する（HTML / CSS を編集）。
4. **こまめに保存**：`Ctrl + S`。

> くり返しになりますが、編集していいのは `drafts/` の中だけです。

---

## STEP 3. ブラウザで見た目を確認する

1. 編集中のHTMLファイルを開いた状態で、**右クリック →「Show Preview」**（Live Preview）
   または **「Open with Live Server」**（Live Server）。
   - 保存するたびに自動で更新されます。
2. スマホ表示を見たいときは、プレビュー幅を狭めるか、ブラウザで開いて `F12` → `Ctrl + Shift + M`。

---

## STEP 4. 変更をセーブして GitHub に送る

### ① コミット（セーブポイントを作る）
1. 左の**ソース管理アイコン**（枝のマーク）をクリック。
2. 変更したファイルが一覧に出る。
3. 上の入力欄に、何をしたか短くメモ（例：`ヘッダーの色を変更`）。
4. **「✓ コミット」** ボタンを押す。
   - 「ステージしますか？」と聞かれたら「はい/Yes」。

### ② 同期（GitHubに送る）
- **「変更の同期」**（Sync Changes）ボタンを押す。
  → 最新の取り込みと、自分の変更の送信をまとめてやってくれます。
- 送信が終わったら、オーナーに「`drafts/〇〇.html` を直しました」と一声かければ完了。

---

## 毎回の作業の流れ（まとめ）

```
VS Code を開く
  ↓ 🔄同期（最新を取り込む）← まずこれ
drafts/ の中のファイルを編集 → Ctrl+S
  ↓ プレビューで確認
コミット（セーブ）
  ↓ 変更の同期（GitHubに送る）
オーナーに一声かける
```

---

## 困ったときのコツ

- **作業を始める前に必ず 🔄同期**（最新にしてから編集）。これで食い違いを防げます。
- 「同期」でエラーが出たら、もう一度「同期」を押すと直ることが多い（先に最新を取り込みます）。
- どう直すか迷ったら、勝手に大改造せず**オーナーに確認**。
- 操作ミスしても、コミットしてあれば**元に戻せます**。慌てずオーナーに相談を。
- **`drafts/` の外は触らない**。これだけ守れば事故はほぼ起きません。
