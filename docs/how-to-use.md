# how-to-use.md

このフォルダ（`NewProject`）を使ってWebサイトを制作するための手順書。

---

## 前提：必要なもの

- **VS Code**（コードエディタ）
- **Claude Code 拡張機能**（VS Code に追加済みであること）

---

## Step 1. テンプレートをコピーする

`NewProject` フォルダをまるごとコピーし、案件名にリネームする。

```
例：
NewProject → clinicHP
NewProject → cafe-official
```

> ⚠️ `.git` フォルダが含まれている場合は削除する。各案件は新しいリポジトリにする。

---

## Step 2. VS Code で開く

リネームしたフォルダを VS Code で開く。

---

## Step 3. Claude Code でプロジェクトを初期化する

VS Code 内の Claude Code（チャット欄）に以下をそのまま貼り付けて送信する：

```
新しいプロジェクトを始めます。docs/project-setup.md を読んで進めてください。
```

Claude Code が自動で質問してくる：

- プロジェクト名
- 入口ページ名
- デザイン素材の有無

答えると、フォルダ作成・`index.html` の調整・ログ初期化まで自動で行われる。

---

## Step 4. デザインの見本（入力）を用意する

デザインの参照元は、用途に応じて以下を使う。

- **既存HPのURL**（リニューアル・既存サイトの整理）→ チャットでURLを伝える
  - Claude Code が内容を読み取り、構成・テキスト・ページ構造を把握する。
  - ⚠️ URLからは「正確な見た目（余白・色・フォント）」までは取りきれない。
    構成・内容の整理に有効。レイアウトの細部は会話で補足する。
  - ⚠️ ログインが必要なページ・動的生成部分は取得できないことがある。
- **デモHTML・カンプ画像・PDF（あれば）** → `drafts/` に置く（デザインの見本）
- **テキストでの指示**（口頭・箇条書き）→ チャットで伝える

本番でサイトに載せる画像（写真・ロゴ等）は `assets/img/`（出力）に置く。

準備ができたら Claude Code に「準備できました（URLは〜）」と伝えると、
**そのまま同じセッションで設計フェーズへ自動的に進む**。

---

## Step 5. 設計フェーズ

Step 4 の続きとして Claude Code が自動で進める。（別途プロンプトの入力は不要）

完了すると `design/page-{page-name}.md`（設計書）が生成される。

---

## Step 6. コーディングフェーズ

**新しいセッション**を開き、チャット欄に以下を貼り付けて送信する
（設計フェーズで読み込む情報が多いため、セッションを分けると安定する）：

```
プロジェクト名：{project-name}
ページ：{page-name}

Task: {page-name} ページのコーディング を開始します。
docs/workflow-coding.md を読んで進めてください。
```

完了すると `{page-name}.html`（ルート直下）と `assets/css/{page-name}.css` が生成される。

---

## Step 7. ブラウザで確認する

ルート直下の `{page-name}.html` をブラウザに直接ドラッグ＆ドロップして確認する。
（CSS・画像は相対パス `assets/...` なので、サーバーがなくても表示される）

- SP表示の確認：`F12` → `Ctrl + Shift + M`（デバイスモード）
- ローカルサーバーは任意（なくても確認できる）

---

## Step 8. 納品・公開

- **最終納品**：完成した一式（HTML / `assets/`）を **レンタルサーバーへFTPアップロード**する。
  - すべて相対パスなので、サーバーのどの階層に置いても動く。
- **デモ共有（任意）**：制作途中のデザインを共有・確認したい場合は GitHub Pages が便利
  → `docs/deploy-github-pages.md` を参照。

---

## Step 9. 共同作業者と進める場合（任意）

デザイン修正を外部に依頼する場合 → `docs/for-collaborators.md` を共有する。

---

## Step 10. 既存ページを改善する（任意）

すでにあるページの **レスポンシブ対応・コード整理・レイアウト崩れ修正** を行う場合は、
新規作成フロー（Step 3〜7）ではなく **既存改善フロー**を使う。改善の広さで2モードある
（詳細は `docs/workflow-edit.md`）。

### 単ページ改善（1ページ / 1セクションを直す）

**新しいセッション**を開き、以下を埋めて貼り付ける：

```
プロジェクト名：{project-name}
対象ページ：{page-name}（例 about.html / assets/css/about.css）
対象範囲：{セクション or ページ全体}（例 sect-about-hero のみ）
改善タイプ：A レスポンシブ / B コード整理 / C 崩れ修正（複数可）
補足：{崩れの再現条件・維持したい見た目など}

Task: 既存ページのコード改善を開始します。
docs/workflow-edit.md を読んで進めてください。
指示した範囲以外は変更しないでください。
```

- **対象範囲を必ず指定**する（指示した範囲以外は変更されない）。
- 崩れ修正（C）のときは、**どの画面幅・どの操作で崩れるか**を補足に書くと精度が上がる。
- 確認は Step 7 と同じ（ブラウザで直接開く／`Ctrl+Shift+M` で SP 確認）。

### サイト全体改善（全ページをまとめて直す）

「サイト全体をレスポンシブ対応したい」「サイト全体のコードを整理したい」ようなケース。
**改善タイプ A / B / C いずれも対応**。**一括では行わず、共通先行 → ページ順次**で進む
（詳細は `docs/workflow-edit.md` の「サイト全体モード」）。

1. **① 棚卸し＋共通方針**を1セッションで実施（例：レスポンシブ=ブレークポイント統一、整理=common.cssの重複排除・命名統一。ヘッダー/フッター/ナビを common.css で確定）
2. **② 各ページ**を、上の「単ページ改善」テンプレートで **1セッション1ページ**ずつ対応
3. 対応済み/未対応は `logs/CHANGELOG.md` のチェックリストで管理し、続きから進める

> なぜ分ける？ → 全ページを一度に触ると崩れの切り分けが難しくなるため。共通部を先に固めると各ページ作業が安定する。

---

## フロー全体図

```
NewProject をコピー・リネーム
  ↓
VS Code で開く
  ↓
Claude Code：「新しいプロジェクトを始めます。docs/project-setup.md を読んで進めてください。」
  ↓（質問に答える → 初期化自動実行）
素材を配置（カンプ→drafts/ ／ 本番画像→assets/img/）→「配置しました」と伝える
  ↓（同じセッションで自動的に設計フェーズへ）
設計書（design/page-{page-name}.md）完成
  ↓
Claude Code：workflow-coding.md を渡す（新しいセッション）
  ↓
HTML（ルート直下）/ CSS（assets/css/）完成
  ↓
ブラウザで確認 → 修正ループ
  ↓
レンタルサーバーへFTP納品（デモ共有は GitHub Pages・任意）

──（既存ページを直したいとき・任意）──
既存HP/CSSがある
  ↓
【単ページ】workflow-edit.md を渡す（範囲を指定）→ 指定範囲のみ修正
  │
  └【サイト全体】共通確定（common先行）→ ページ順次ループ（1セッション1ページ）
  ↓
ブラウザで確認（SP/PC）→ 修正ループ
```
